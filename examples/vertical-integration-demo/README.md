# Vertical Integration Demo

A minimal SPFN + Next.js app that shows one feature wired end to end — from a
database table to a fully type-safe client call — using the SPFN building blocks:
**Entity → Repository → Route → Router → generated client**.

If you want to see how the pieces of SPFN fit together in a single request path,
this is the example to read.

## What it demonstrates

A single `examples` resource implemented as a complete vertical slice:

| Layer | File | What it shows |
| --- | --- | --- |
| **Entity** | `src/server/entities/example.entity.ts` | A Drizzle `pgTable` using SPFN's `id()` / `timestamps()` column helpers |
| **Repository** | `src/server/repositories/example.repository.ts` | `BaseRepository` with `_findMany` / `_findOne` / `_create` / `_updateOne` / `_deleteOne` / `_count` |
| **Routes** | `src/server/routes/examples.ts` | `route.get/post/put/delete` with TypeBox input validation (query, params, headers, body) |
| **Router** | `src/server/router.ts` | `defineRouter({...})` composing every route; its type is the contract for the client |
| **Proxy** | `src/app/api/rpc/[routeName]/route.ts` | `createRpcProxy({ routeMap })` so browser calls reach the API server with cookies/interceptors |
| **Client** | `src/lib/api-client.ts` | `createApi<AppRouter>()` — one type-safe client usable from Server Components, Client Components, Server Actions, and Route Handlers |

The request path looks like this:

```
Next.js component / action
        │  api.listExamples.call(...)        ← fully typed, from AppRouter
        ▼
/api/rpc/[routeName]  (proxy)                ← cookies + interceptors
        ▼
SPFN API server  →  Router  →  Route handler  →  Repository  →  Postgres
```

The route/client contract is bridged by `src/generated/route-map.ts`, which is
**generated by codegen** (`pnpm codegen`) — it carries only method + path, never
server code, so no backend logic leaks into the browser bundle.

## Getting started

> Prerequisites: Node 18.18+, pnpm, and Docker (for a local Postgres).

From the repository root, install workspace dependencies:

```bash
pnpm install
```

Then, inside this directory:

```bash
# 1. Start a local Postgres (and optional Valkey/Redis)
docker compose up -d

# 2. Configure environment
cp .env.local.example .env.local   # defaults match docker-compose.yml

# 3. Generate the route metadata the client imports
pnpm codegen

# 4. Run the SPFN API server + Next.js together
pnpm spfn:dev
```

`pnpm spfn:dev` runs the SPFN backend and the Next.js frontend side by side. You
can also run them separately with `pnpm spfn:server` (backend only) and
`pnpm spfn:next` (frontend only).

### Environment variables

`.env.local.example` lists every variable the app reads:

- `DATABASE_URL` — Postgres connection (defaults match `docker-compose.yml`)
- `SPFN_API_URL` — where the Next.js proxy forwards requests for SSR
- `CACHE_URL` — Redis/Valkey, optional
- `NODE_ENV`, `SPFN_LOG_LEVEL`

## Project layout

```
src/
├── app/
│   ├── api/rpc/[routeName]/route.ts        # SPFN RPC proxy (browser → API server)
│   ├── layout.tsx
│   └── page.tsx                           # UI (extend this to exercise the API)
├── generated/
│   └── route-map.ts                       # generated by `pnpm codegen`
├── lib/
│   └── api-client.ts                      # type-safe client (createApi<AppRouter>)
└── server/
    ├── entities/example.entity.ts         # Drizzle table + types
    ├── repositories/example.repository.ts # BaseRepository data access
    ├── routes/                            # route definitions (examples, health, root)
    └── router.ts                          # defineRouter — the API contract
```

## Calling the API from a component

Once `pnpm codegen` has generated the metadata, every route is available on the
typed `api` client:

```typescript
import { api } from '@/lib/api-client';

// List (typed query, typed response)
const { examples, total } = await api.listExamples.call({ query: { limit: 10 } });

// Create
const created = await api.createExample.call({
    body: { name: 'Hello', description: 'from the demo' },
});
```

The same `api` object works in Server Components (direct), Client Components
(through the `/api/actions` proxy), Server Actions, and Route Handlers.
